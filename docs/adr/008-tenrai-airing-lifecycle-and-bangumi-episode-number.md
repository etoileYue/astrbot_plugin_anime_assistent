# ADR-008：以 Tenrai `airing` 管理提醒生命周期，以 Bangumi 分集确认提醒集数

## 背景

自动提醒原本只使用 Tenrai 的播出排期判断通知时机，无法在作品完结后自动停止；通知也不包含用户实际关心的正片集数。仅按总集数、条目状态或搜索结果的其他状态字段判断完结，会引入不同数据源之间不一致的问题。另一方面，Tenrai 的排期适合给出预计播出时刻，却不适合作为 Bangumi 作品的分集编号来源。

## 决策

继续只调用 Tenrai 搜索接口，且仍严格匹配 Bangumi 日文原名。对匹配结果同时读取 `mal_id`、`broadcast` 和布尔 `airing`：

- `broadcast` 转为北京时间，用于自动排期；每轮后台检查可刷新自动排期。
- `airing=false` 写入 `subscriptions.airing=0`，自动停止提醒；不主动发送完结消息，也不清除原排期。
- 手动排期也会查询 `airing`，但绝不改写用户填写的星期和时间。
- 通知时机跨越排期后，调用 Bangumi 分集接口，以该日期的 `type=0` 正片 `airdate` 确认集数，发送“预计更新第 N 集”。无法确认时跳过本次通知。

不新增 Tenrai 详情接口，也不依据 Tenrai `status` 判断生命周期。

## 原因

- Tenrai 搜索结果已同时提供排期和连载生命周期，避免额外请求与额外关联风险。
- 只把 `airing=false` 视为停用依据，可避免从模糊状态文本推断完结。
- Bangumi 分集的 `type`、`ep` 与 `airdate` 是确认 Bangumi 正片集数的权威数据，能排除 SP、OP、ED 等非正片章节。
- 查询失败、标题不匹配或分集未出现时保留已有配置并不发送无集数通知，能避免临时上游问题造成误停或误报。

## 替代方案

- 用 Tenrai/MAL `status` 或 Bangumi 条目状态判断完结：字段语义和更新速度不稳定，且不符合搜索结果已提供 `airing` 的数据边界。
- 调用 Tenrai 详情接口补充信息：增加请求量和失败面，当前没有必要。
- 根据总集数或最新分集猜测通知集数：特别篇和数据延迟会导致错误编号。
- 继续发送不含集数的提醒：不能满足用户识别当前更新内容的需求。

## 影响

- `subscriptions.airing` 成为提醒是否启用的持久化状态；值为 `0` 的条目不参与有效排期扫描。
- 列表以 `🔄` 标记仍在连载的条目；已完结条目不追加提醒状态文字。
- 每轮检查会额外对启用提醒执行 Tenrai 搜索，并在真正需要通知时按条目查询 Bangumi 分集。
- 手动排期仍优先于自动排期，但不能绕过 Tenrai 确认的完结生命周期。
