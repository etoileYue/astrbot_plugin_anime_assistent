# ADR-006：以 Jikan 播出排期驱动更新提醒

## 背景

原提醒任务逐部查询 Bangumi 分集，并以最新集数变化推送消息。这既增加了 API 调用，也不能在预计播出时间及时提醒，且集数数据更新滞后时容易产生错误的“已更新”表述。

## 决策

使用公开 Jikan v4 搜索结果中的 MAL `broadcast` 排期驱动提醒。只接受前五个搜索结果中、规范化后与 Bangumi 日文原名完全相同的 `title_japanese`；将星期、时间和 IANA 时区转换后，统一保存为 `Asia/Shanghai`（北京时间）。用户手动填写的北京时间排期优先，且可关闭或重新自动匹配。

## 原因

- 播出时刻比 Bangumi 分集出现更适合“预计更新”提醒。
- 严格日文原名匹配优先避免同名或译名造成的错误关联。
- 统一保存北京时间使列表、命令和通知无须让用户换算时区。
- Jikan 为公开 API，不需要额外密钥。

## 替代方案

- 继续轮询 Bangumi 分集：无法提供排期提醒，调用量也更高。
- 以中文名或模糊匹配关联 MAL：覆盖率可能更高，但错误关联风险不可接受。
- 要求用户全部手动设置：可靠但增加日常操作成本。

## 影响

- `subscriptions` 需要保存 MAL ID、排期、来源、查询状态和提醒标记，并通过迁移兼容旧数据库。
- 调度器不再用 Bangumi 分集 API 决定更新；该接口仅保留给观看进度和访谈流程。
- 自动查询必须遵守 Jikan 限速并在失败时允许用户手动覆盖。
